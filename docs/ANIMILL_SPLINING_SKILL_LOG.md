# ANIMILL splining skill log

This file records verified, reusable decisions for a future Codex skill. It is
not the skill package yet. Add lessons only when a real integration proves or
falsifies them.

## Product center

ANIMILL standards are the center. The HTML tools and repositories under
E-drives are specialized capability fragments created to be absorbed into one
coherent creative system. OpenMontage, NANA, browser tooling, prompt systems,
renderers, talking-head tools, and future niche apps are peers in that library;
none automatically becomes the product shell.

`UNIFIED SYSTEM = valuable niche logic + ANIMILL interaction standards + spline adapter + shared state + cross-component benefit`

The master repository list is not inspiration or a reading list. It is a
finite capability-integration queue. Most repositories contribute working
"nerves"—browsing, scraping, generation, editing, rendering, audio, automation,
or distribution—which must terminate in ANIMILL's shared state and interaction
standards.

Competition folders such as Higgsfield, TapNow, Pine Drama, and similar niche
collections are a different input class. Their genre, title, niche, prompt, and
workflow maps feed domain intelligence into generators, presets, discovery,
and validation. They are not automatically applications to embed or skins to
copy.

## ANIMILL standards learned so far

- Typography, palette tokens, panel depth, bevel geometry, spacing, and compact
  behavior come from the ANIMILL shell.
- Transport, scrubber, ruler, tracks, clips, selection, inspector, and direct
  editing use one shared interaction language.
- Collapsed side panels surrender their space to the remaining workspace.
- Hover feedback never changes geometry. Pointer light and reticle live on a
  stable compositor layer above translucent panels without replacing content
  transforms.
- Every visible control edits canonical state. Save, reload, handoff, preview,
  and render consume that same state.
- Provider availability, fallbacks, rights, provenance, and renderer
  differences remain explicit.
- Local/offline authoring is a first-class path, including repository media.

## Splining method learned so far

1. Inspect a fragment as a working niche product. Identify its unique useful
   logic, inputs, outputs, state, and proven controls before changing its shell.
2. Preserve the niche capability; remove duplicate navigation, styling,
   transport, timelines, inspectors, and project models.
3. Map the fragment into the smallest shared ANIMILL contract. Adapt at the
   boundary instead of rewriting the fragment or weakening the core model.
4. Apply ANIMILL chrome and interaction primitives. A reskin is incomplete if
   state, editing, or handoffs remain isolated.
5. Expose the fragment only where it benefits the current creative flow. Clean
   components should merge into one another instead of appearing as a catalog
   of disconnected mini-apps.
6. Preserve IDs, timing, geometry, media, audio/voice data, provenance, and
   user work through every boundary.
7. Prove one real vertical slice with fresh input through editor, inspector,
   timeline, save/handoff, and any claimed renderer. Do not count documentation
   or a hidden data field as integration.
8. Record what the newly connected fragment gives other components and what it
   receives from them. Mutual benefit is the acceptance criterion for synergy.

## Two intake contracts

### Functional nerve

A repository enters through a capability port, not as another standalone page.
Its useful runtime is exercised first, then connected to shared ANIMILL inputs,
outputs, state, progress, errors, provenance, and offline behavior. Existing
HTML may be reused inside the app while the duplicate shell is removed.

`NERVE SPLINE = proven function + ANIMILL port + canonical state + visible control + downstream consumer + fresh proof`

### Intelligence pack

A competition or niche folder enters through a knowledge port. Extract its
taxonomies, workflow stages, constraints, prompt variables, genre/title
patterns, and provider observations into attributable structured data. That
data must power an existing decision, generator, preset, or check; merely
displaying or summarizing the folder does not clear it.

`INTELLIGENCE SPLINE = attributable domain map + normalized schema + named consumer + visible effect + provenance`

## Clearance rule

Every source in the master list must finish in one explicit terminal state:

- **integrated:** connected to ANIMILL and freshly proven;
- **absorbed:** its reusable data or logic now lives behind an existing shared
  component;
- **duplicate:** an already integrated component covers it, with the replacement
  named;
- **rejected:** unsafe, broken, legally unsuitable, or incapable of adding
  distinct value, with evidence;
- **parked:** deliberately deferred for a named dependency, not vague future
  consideration.

"Inspected," "mapped," "documented," and "reskinned" are intermediate states,
not clearance. The queue shrinks only when a source reaches a terminal state
and its ANIMILL consumer and proof are recorded.

## Verified implementation lessons

- `ANIMILL.compose(spec)` is a useful common intake boundary for prompt, world,
  talking-head, and audio-aware scene specifications.
- Extra world/talking-head metadata must survive normalization and remain
  visible in the authoring interface, not merely in exported JSON.
- Talking-head intent can materialize through ANIMILL's existing editable video
  block instead of introducing a second scene model.
- Repository-local media needs two paths: browser serving for authoring and
  job-local materialization for deterministic renderers.
- Acquired research must become canonical project context, not ephemeral modal
  state. One pinned source can then ground generators, label derived assets,
  appear in the authoring UI and rights report, survive save/reload, and feed
  every downstream adapter without another scrape.
- Audible HyperFrames video must declare `data-has-audio="true"`; otherwise a
  strict renderer correctly rejects the composition.
- A downstream adapter may derive its own scene plan, but the ANIMILL project
  remains canonical. OpenMontage currently proves this pattern; it does not own
  the overall architecture.

## Failure patterns to prevent

- Promoting one fragment—especially a repository or renderer—into the product
  center because it was recently integrated.
- Building new providers or controls before searching E-drives for an existing
  implementation.
- Rewriting niche logic when a boundary adapter and standardized UI will work.
- Calling a modal, metadata preservation, unit test, or visual reskin a complete
  integration without a usable end-to-end path.
- Spending more effort describing progress than delivering a visible capability.
